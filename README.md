# codex-brain

**给 Codex 用的独立项目记忆库：正常开工时自动建档，结束时说一句“收尾”，保存进度并把项目和大脑同步到 GitHub。**

这里集中保存项目目标、已确认的决定、当前断点和下一步。代码仍放在各自的项目仓库；本库帮助下一次聊天或另一台电脑接上开发进度。

本库与 DeepSeek Harness（DSH）原来的 `agent-brain` 分开管理，不迁移旧项目，不修改 DSH 的配置、技能或路径标记。

## 日常怎么用

安装配置完成后，不需要记住“建立大脑档案”这个额外口令。

| 场景 | 可以直接对 Codex 说 | 按本库规则执行的动作 |
|---|---|---|
| 新建项目 | “新建一个记账工具，按开发规范做。” | 确认真实项目根和目标后自动建立最小档案 |
| 继续项目 | “继续这个项目。” | 读取该项目的 CONTEXT/NEXT，结合当前代码核对断点 |
| 结束开发并上传 | **“收尾。”** | 补建缺失档案、保存记录、提交并同步项目和大脑 |
| 只保存本地 | “保存进度，暂不上传。” | 更新本地笔记，不提交或推送 |
| 明确恢复某个项目 | “先读记账工具的大脑笔记，再核对代码继续。” | 定位对应档案，按需查决策和历史 |

“收尾”的对象必须是当前明确的 Codex 开发项目。如果聊天同时涉及多个项目，或只是讨论“收尾”这个词的含义，不会直接把某个文件夹上传。

项目有界面时，仍要遵守已有 UI 设计与用户门禁。自动建档不代表需求、设计或实现已经获批。

## 它怎样保存和恢复进度

本库由三部分配合工作：

1. **Codex 全局约定**：提示 Codex 在明确的开发任务中定位本库、读取档案，并把实际“收尾”交给专用技能。
2. **`codex-brain-handoff` 技能**：定义项目识别、建档、保存、提交和 GitHub 同步步骤。
3. **Markdown 笔记与 Git**：把有价值的项目状态落到文件，再通过仓库进行备份和跨电脑交接。

保存分三个时点：

- **开工时**：自动检查档案；没有则建立最小记录，不要求用户另发口令。
- **关键决定获确认或阶段结束时**：保存本地摘要，减少全部依赖最后一次聊天回忆的情况。
- **收尾时**：再次补查缺档，整理断点并执行 GitHub 同步。

恢复时先读 `CONTEXT.md` 和 `NEXT.md`，按任务查 `DECISIONS.md`，需要追溯时再看 `JOURNAL/`。同时核对实际文件、分支、提交和未提交修改，不能把旧笔记里的“测试通过”当成本次已经验证。

这里的“自动”是指 **Codex 读取已安装的规则后按约定执行**。本库提供指令、技能和文件格式，没有后台常驻服务；单独克隆仓库也不会完成安装。突然关闭聊天而没有下达“收尾”，不会触发后台上传，已经落盘的本地记录仍会保留。

## 说收尾后会做什么

对当前明确项目下达“收尾”，即按本库约定执行以下流程，常规建档、提交、建私有仓和推送不再逐项询问：

1. **定位项目**：核对实际项目根、本机绑定和完整远程仓库身份，避免把 `app`、`outputs`、`work` 或整个上层工作区当成项目。
2. **补齐档案**：没有档案就自动建立四件套，已有档案则整理本次真实产出、已确认决定和下一步。
3. **检查提交范围**：核对待上传文件、已跟踪内容和拟推送历史，排除凭据、账号快照、个人资料、缓存及无关文件。
4. **保存项目代码**：按项目既定要求验证，只暂存明确属于本次范围的文件，有变动才提交。
5. **同步项目仓库**：已有远程则核对后复用；没有远程则在目标账号下创建私有仓库并推送当前明确分支。
6. **更新大脑笔记**：写入项目最终提交、实际验证结果、同步状态和交接断点，再提交并推送独立大脑。
7. **核对同步结果**：比较远端分支 SHA 与本地提交，分别报告项目和大脑的仓库链接、分支、提交及成功或失败状态。

维护的项目如果就是 `codex-brain` 本身，两者视为同一个同步目标，不重复建仓或复制。包含收尾日志的提交也不会被要求在日志里自引用自己的最终哈希。

没有改动时跳过空提交。尚未通过验收的工作可以按 WIP 保存，但会明确记录失败与未验证部分；收尾不等于部署上线、创建 Release 或发布安装包。

用户当次说“只保存本地”“不要上传”等限制时，以当次限制为准。

## 代码与大脑分别传到哪里

| 内容 | 保存位置 | 说明 |
|---|---|---|
| 业务项目代码和必要资源 | 每个项目自己的 GitHub 仓库 | 一个项目一个仓库，不把所有项目代码堆进大脑 |
| 项目背景、决定、断点和历史摘要 | `ljr282341583/codex-brain` | 本独立大脑仓库 |
| Codex 收尾技能源、模板和全局规则分发区块 | 本库 `outputs/` | 用于维护与换机器恢复 |
| 原 DSH 的笔记与技能 | 原 `agent-brain` | 本流程不修改或自动接管 |

当前目标账号为 **`ljr282341583`**，执行前会核对 GitHub CLI 的登录账号。新建仓库默认 **私有**；已有仓库保持原来的可见性，不因收尾被擅自改变。

中文项目名可以保留为本地项目名和笔记 ID，GitHub 仓库使用稳定的 ASCII 名称，首次选定后记入绑定。遇到同名远程时先核对，不能把无关本地项目直接推入一个已有同名仓库。

## 仓库目录与四件套

```text
codex-brain/
├── README.md                         GitHub 首页与总说明
├── AGENTS.md                         本库自身的维护约定
├── .gitignore                        排除 work、环境文件等内容
└── outputs/
    ├── README.md                     本机路径、操作与恢复细节
    ├── brain-config.example.json     配置参考，换机器必须调整路径
    ├── INSTALLATION.json             本机安装信息与历史记录
    ├── skills/
    │   └── codex-brain-handoff/
    │       └── SKILL.md              专用收尾技能分发源
    ├── templates/
    │   ├── CODEX-AGENTS.md           Codex 全局管理区块
    │   ├── CONTEXT.md
    │   ├── NEXT.md
    │   ├── DECISIONS.md
    │   └── JOURNAL.md
    └── 项目/
        └── <project_id>/
            ├── CONTEXT.md
            ├── NEXT.md
            ├── DECISIONS.md
            └── JOURNAL/
                └── YYYY-MM-DD-HHmmss-Codex.md
```

本机另有被 Git 忽略的 `work/`，用于备份、草稿和验收样本。它不会随 GitHub 克隆恢复；需要跨电脑恢复的技能源、模板与说明都放在 `outputs/`。

| 档案 | 记录什么 | 维护方式 |
|---|---|---|
| `CONTEXT.md` | 项目目标、代码位置、稳定约束和关键入口 | 更新已确认的稳定事实 |
| `NEXT.md` | 当前状态、可直接执行的下一步、阻塞和验证边界 | 保留当前断点，已解决旧事项移入日志 |
| `DECISIONS.md` | 用户已经确认的决定、理由与取代关系 | 追加记录，旧决定保留并注明被取代 |
| `JOURNAL/` | 每次保存的产出、代码状态、验证和交接摘要 | 追加新日志，不覆盖历史 |

笔记只写结论、理由和证据摘要，不搬运整段聊天、大量代码或敏感配置。没有做过的测试如实写“未验证”，没有确认的建议不写成既定决定。

## 与 DSH 的隔离边界

| 项目 | DeepSeek Harness | Codex |
|---|---|---|
| 大脑仓库 | 原 `agent-brain` | 独立 `codex-brain` |
| 本机定位 | 原 `.agent-brain` 文件 | Codex home 下 `brain-config.json` |
| 全局入口 | 原 `.dsh/AGENTS.md` | Codex 自己的 `AGENTS.md` 管理区块 |
| 收尾技能 | 原共享 `session-handoff` | 独立 `codex-brain-handoff` |
| 已有项目 | 原样保留 | 不自动导入或认领 |

本流程不修改 `.dsh`、共享 `.agents/skills/session-handoff`、原大脑或 `.agent-brain` 标记。用户明确要求跨工具接手某个项目时，再单独确定读取和写回范围。

## 新电脑安装与恢复

### 1. 准备工具并克隆

当前安装与验收环境为 Windows。新电脑需要可用的 Codex、Git 和 GitHub CLI，以及访问本私有仓库的账号权限。

在 PowerShell 中登录 GitHub，并确认账号：

```powershell
gh auth login
gh api user --jq .login
```

选择本机的固定目录，下面沿用原机器的路径作为示例：

```powershell
$brainRoot = 'G:\ai\codex projects\projects\01_软件开发\codex-brain'
git clone https://github.com/ljr282341583/codex-brain.git "$brainRoot"
```

如果已经克隆过，复用原目录并检查 Git 状态，不重复克隆，不覆盖本地未保存修改。盘符或项目目录可以不同，随后配置必须填写新机器的实际路径。

### 2. 让 Codex 按仓库说明完成接入

可以直接把下面这段话交给新机器上的 Codex，把路径替换成实际克隆位置：

> 读取 `<本机仓库路径>\README.md` 和 `outputs\README.md`，按说明安装这个独立 Codex 大脑。安装专用技能，配置本机 brain-config.json，合并全局管理区块；保留已有规则和项目绑定，不修改 DSH。完成后核对技能、路径和本库维护档案的读取结果。

本库提供的是技能源、模板、配置示例和安装说明；当前由 Codex 按说明接入，没有双击安装器。

具体需要配置三处：

| 内容 | 本机位置与操作 |
|---|---|
| 专用技能 | 将 `outputs/skills/codex-brain-handoff/` 安装到当前 Codex home 的 `skills/`；默认 home 为用户目录下 `.codex` |
| 本机配置 | 参考示例，在当前 Codex home 下创建或合并 `brain-config.json`，调整本机路径 |
| 全局管理区块 | 将 `outputs/templates/CODEX-AGENTS.md` 合并进当前 Codex home 的 `AGENTS.md`，保留区块外内容 |

若使用自定义 `CODEX_HOME`，上述三处必须使用同一个 Codex home。同名技能、配置或区块已经存在时先检查差异，不整份覆盖。

`brain-config.json` 是本项目约定的定位文件，由技能读取，不是往 Codex 内置 `config.toml` 中添加的一组设置。

### 3. 验证接入

让 Codex 说明它实际读到的配置、技能和笔记位置，并读取本库的 [CONTEXT](outputs/项目/codex-brain/CONTEXT.md) 与 [NEXT](outputs/项目/codex-brain/NEXT.md)。如果新技能尚未出现在当前聊天，重新打开聊天后再检查。

新机器的项目绑定按实际代码位置重建。全新安装从空绑定开始；已有配置则保留原绑定，核对后再追加，不能把旧机器的绝对路径原样复制过去。

### 4. 恢复业务项目

分别克隆需要继续的业务项目与本大脑，打开实际业务项目，再让 Codex 根据完整远程身份定位笔记。代码与笔记都要核对，不能只克隆大脑就认为业务代码也已经恢复。

## 配置与项目识别

配置字段和完整路径参考见 [brain-config.example.json](outputs/brain-config.example.json)，原机器的具体部署见 [本机操作说明](outputs/README.md)。

| 字段 | 作用 |
|---|---|
| `owner` | 必须为 `codex`，避免误用其他工具的大脑 |
| `repository_root` | 本机独立大脑仓库根目录 |
| `notes_root` | 本库项目笔记根目录 |
| `templates_root` | 四件套模板位置 |
| `skill_source` | 专用技能分发源；安装技能不可用时的读取入口 |
| `project_bindings` | 本机项目 ID、实际代码根、完整远程身份及 GitHub 仓库映射 |
| `protected_roots` | DSH 等受保护位置，不能与独立大脑路径重叠 |
| `archive_policy` | 开工建档、收尾补档和已确认决定落盘约定 |
| `handoff` | 收尾触发词、GitHub 账号、默认私有、两仓同步和大脑仓库名 |

有 Git 的项目先核对仓库根与完整远程身份；没有 Git 的项目使用当前任务已经明确的项目根。项目根是包含多个项目的上层目录、同名项目身份不同或映射不确定时，先明确范围。

示例配置中的路径属于原安装机器，只能作为参考。真正生效的是当前机器 Codex home 下的配置；不要在任何一份配置中写入 GitHub token、密码或账号快照。

## 异常时怎样处理

| 情况 | 处理方式 |
|---|---|
| 收尾时发现没有档案 | 自动补建，再记录本次真实信息；早期上下文缺失要说明，不能编造历史 |
| 没有 Git 仓库或远程 | 在明确项目根初始化；核对账号后按规则创建私有远程 |
| GitHub 登录账号不符或没有权限 | 保留本地进度，说明具体账号或权限问题，不自动切换身份 |
| 远程仓库同名但归属不明 | 核对或使用不冲突名称，不把代码推入一个未知已有仓库 |
| 有凭据或不明敏感文件 | 排除可明确排除的新文件；已进入跟踪内容或历史的秘密先处理，不直接上传 |
| 推送被拒或远端出现分歧 | 先诊断并报告，不自动 pull/rebase、强推、重置或改写历史 |
| 项目已推送，大脑推送失败 | 分别报告结果并保留本地笔记，不宣称两边全部成功 |
| 网络中断，结果不明确 | 先查询远端实际状态，再重试，避免重复建仓 |
| 专用技能加载失败 | 按配置读取技能分发源；两处都不可用则报告，不回退到 DSH 技能 |

这些是实际阻塞时的处理，不会把正常收尾重新拆成一连串常规确认。删除电脑文件仍须获得用户允许。

## 常见问题

**新项目还要说“建立大脑档案”吗？**

不用。项目与目标明确后自动建档；收尾再兜底检查。

**还要说“Codex 大脑收尾”，还是说“收尾”就行？**

说“收尾”即可，前提是当前明确在处理哪个 Codex 开发项目。只想本地保存时说“保存进度，暂不上传”。

**项目会自动变成公开仓库吗？**

新仓默认私有。已有仓库不自动改变可见性；内容是否适合原有公开范围不明确时先核对。

**这个大脑会自动记住聊天里的所有内容吗？**

保存的是经过整理并实际写入 Markdown 的项目摘要，不是整段聊天或模型训练数据。没有落盘的内容不能靠 Git 恢复。

**多个项目会共用一个代码仓库吗？**

各项目使用各自的代码仓库，大脑集中保存对应笔记。维护 `codex-brain` 自身时才作为同一个同步目标处理。

**安装以后会改 DSH 的东西吗？**

按本库规则只接入 Codex 独立入口，原 DSH 大脑、共享技能和路径标记保持原样。

**换机器后为什么还要配路径？**

Git 同步笔记与分发源，但机器盘符、代码位置、Codex home 和登录凭据各不相同；`work/` 本机备份也不在仓库里。
