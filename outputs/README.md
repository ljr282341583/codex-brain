## 平时怎么说

第一个真实项目开始时，正常告诉 Codex 要做什么，例如：

> 在 Codex 项目目录中新建“我的项目”，按现有开发规范做。

不用另说“建立大脑档案”：开工时自动建立最小档案，重要决定确认或阶段完成时保存本地摘要，收尾时再次检查，漏建则补建。

有界面的项目仍然先走 UI 设计和用户门禁。建立记忆档案不代表已批准产品设计或实现。

开发告一段落时：

> 收尾。

这表示执行自动建档、保存摘要、项目提交、必要时建私有仓库、推送项目与独立大脑。只想本地保存时说“保存进度，暂不上传”。在聊天中讨论“收尾”的含义不会触发实际上传。

在同一项目重新打开聊天后：

> 先读这个项目的 Codex 大脑笔记，结合当前代码核对断点，再继续。

也可直接调用 `$codex-brain-handoff`。普通聊天、独立问答、处理一份临时材料不会自动建立项目档案。

## 一个项目记什么

```text
outputs/项目/<project_id>/
├── CONTEXT.md       项目目标、代码位置、约束和关键入口
├── NEXT.md          当前状态、下一步、阻塞项及验证边界
├── DECISIONS.md     用户已确认的决定及其理由
└── JOURNAL/         每次保存一篇，记录事实和证据
```

项目身份使用真实仓库根、完整远程身份和本机显式绑定，不把 `app`、`outputs` 等子目录名当项目名。绑定保存在本机配置的 `project_bindings`，不从 DSH 项目登记表导入。首次真实建档后由技能维护绑定，记下项目使用的 GitHub 仓库身份。

`CONTEXT` 和 `NEXT` 先读；决策按任务查，流水日志按追溯需要查。笔记是当时记录，实际代码、当前 Git 状态和真实验证证据需要重新核对。

## Git 与同步

用户在 Codex 当前开发项目实际下达“收尾”，即执行这套约定中的自动建档、提交、必要时建私有仓库和推送，不再重复问“是否建档／是否提交／是否建仓”。“保存进度”默认只保存本地，用户当次的范围限制优先。

配置中的 GitHub 目标账号为 `ljr282341583`，每次执行先核对登录账号。项目使用自己的仓库，大脑使用独立的 `ljr282341583/codex-brain`。仓库尚不存在时才创建，均默认私有；已有远程复用并核对身份与权限，不擅自改变可见性。中文项目名需要稳定的 ASCII 仓库名，首次选定后写入绑定。发生同名冲突时不把本地内容直接推入已有不明仓库。

只上传本项目的源代码、必要资源和笔记，排除凭据、账号快照、个人数据、依赖／缓存和无关大文件；同时核对已跟踪文件和拟推送历史。普通“私有仓库”不能代替凭据检查。只暂存本次明确涉及的文件，不执行无范围的 `git add -A`。

先提交并推送项目，再把最终项目 HEAD 和同步结果写进笔记，随后提交推送大脑。两边分别核对远端分支 SHA。没有变动则不造空提交。未验收的工作可用 WIP 提交保存，不因此被宣称可发布；收尾不等于部署、创建 Release 或发包。

项目归属不清、存疑秘密已经进入历史、账号不符或远程分歧时，先保留本地进度并报告具体阻塞。推送被拒不自动 pull/rebase、强推或改写历史；部分成功分开报告，不把本地保存说成已经同步。

以后换电脑时，克隆项目与独立 `codex-brain`，安装本技能并配置该电脑的路径即可，无需修改 DSH。没有实际下达“收尾”的突然关闭不会触发后台上传；已经落盘的本地检查点仍保留。

## 新机器恢复

让新机器上的 Codex 读取本文件，并按以下范围安装：

1. 将 `outputs/skills/codex-brain-handoff/` 安装到该机器 Codex home 的 `skills/`；同名已有技能先检查差异，保留已有改动。
2. 参考 `outputs/brain-config.example.json`，把仓库、笔记、模板、技能源、受保护路径改成该机器的实际路径，保存到该机器 Codex home 的 `brain-config.json`。不要原样沿用旧机器路径；本机 `project_bindings` 从空开始，接手项目时结合实际代码根和完整远程身份重建。
3. 将 `outputs/templates/CODEX-AGENTS.md` 中的独立管理区块合并进该机器 Codex home 的 `AGENTS.md`，保留区块外内容；若已有同名区块，先对照差异而非重复追加。模板中的旧 DSH 路径仅是原机器的保护提示，新机器以实际受保护路径为准。
4. 核对专用技能和配置可读，先读取本库自身的 CONTEXT/NEXT，再处理实际项目。凭据由该机器自己的 GitHub CLI 登录提供，本库不保存凭据。

这四步只安装 Codex 自己的入口，不修改 DSH。仓库内的安装验收与本地 Git 演练报告是对应日期的历史证据，不应被当作新机器已经验收。

## 与 DSH 的隔离边界

- 不覆盖 `%USERPROFILE%\.agent-brain`，不使用它定位 Codex 笔记。
- 不改 `%USERPROFILE%\.dsh\AGENTS.md`、共享 `.agents\skills\session-handoff` 或原 `agent-brain`。
- 原大脑中的项目不会被复制或自动认领。
- Codex 默认使用自己的 `codex-brain-handoff`，不用 DSH 的 `session-handoff` 进行本库收尾。
- 没有找到 Codex 档案时按新项目处理；同名或身份不明确时先核对，不跳去 DSH 查找并写入。
- 用户明确要求接手一个 DSH 项目时，另行确定读取和写回范围。

## 回退

本次应用已经向当前聊天重新注入全局入口；若新安装技能尚未出现在当前聊天，重新打开聊天后再试。文件检查和磁盘保存恢复验证不等于已验证真实项目中的完整技能选择与云端上传行为，后者需要在实际收尾时确认。
